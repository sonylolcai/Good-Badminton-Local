# 当前视频解析数据与目标技战术数据对照

## 结论

模拟样例并不等于当前程序已经能从真实视频中产出全部字段。当前程序可以直接产出球员二维位置、球场位置、手腕位置、粗略速度和羽毛球图像位置；模拟样例中的三维球轨迹、击球类型、击球者、战术意图、失误归因和能力评分目前仍是目标字段。

## 字段对照

| 数据 | 当前真实视频能否得到 | 说明 |
|---|---|---|
| `frame`、`time_sec` | 可以 | 当前 `detections.jsonl` 已保存。 |
| 上/下半场球员图像坐标 | 可以 | 当前按脚踝中点计算；远端存在漏检。 |
| 球员球场坐标 `(x,y)` | 可以 | 依赖正确球场四角和透视映射。 |
| 左右手腕图像坐标 | 可以 | 当前已保存；低置信关键点可能缺失。 |
| 粗略球员速度 | 可以 | 当前已计算，但需要统一10Hz、平滑和可信度。 |
| `track_id` | 不可以 | 当前只有固定的 `upper/lower` 槽位，需要接入ByteTrack。 |
| `detected/predicted/missing` | 不可以 | 当前缺少来源状态和置信度。 |
| 加速度、方向、场区 | 可以派生 | 可由有时间戳的球场位置计算，但加速度容易放大抖动。 |
| 姿态质量和完整17关键点 | 部分存在但未保存 | 模型内部有关键点，当前输出只保存左右手腕。 |
| 羽毛球图像坐标 | 可以 | 当前只有二维像素位置，远端和高速阶段存在漏检。 |
| 羽毛球球场二维坐标 | 只能近似 | 空中的球不在地面平面上，直接用球场单应矩阵会产生系统误差。 |
| 羽毛球三维 `(x,y,z)` | 单固定相机不能可靠直接得到 | 需要双机位、已知物理轨迹拟合或专门的单目三维模型。模拟数据中的 `z` 是合成真值。 |
| 羽毛球真实速度km/h | 当前不可以 | 没有可靠三维坐标时只能得到像素速度，不能把它当作真实球速。 |
| 回合边界和回合数 | 当前实现不可靠 | 必须新增回合状态机和置信度，不能再依赖记录帧号空缺。 |
| 击球时刻与击球者 | 当前不可以 | 需要连续球轨迹、手腕/球拍距离和方向突变。 |
| 球路类型和落点 | 当前不可以 | 需要可靠的击球事件与球轨迹。 |
| 下网、出界、未触球 | 当前不可以 | 需要球过网、落点和回合结局。 |
| 受迫/非受迫失误 | 当前不可以 | 还需要对手压力、来球质量、运动状态和规则上下文。 |
| 0～100能力评分 | 不能直接得到 | 评分是派生结果，必须经过样本门槛、同级参考分布和教练标签校准。 |

## 模拟样例中不应直接作为第一版真实字段的内容

- `z_m` 和真实球速：单目固定摄像头暂时没有可靠依据。
- `tactical_intent`、`intended_target`：属于模型推断，应保存置信度，不能当作观测事实。
- `stroke_quality_score` 和综合评分：属于报告层派生值，不应混入原始检测真值。
- 毫秒级准备/回位时间：需要可靠击球时刻后才能计算。
- 10秒单回合失误率：只能描述该回合，不能代表运动员稳定水平。

## 当前样例还缺少但正式产品应该增加的内容

- 模型版本、阈值、推理尺寸和固定机位配置版本。
- 每个字段的来源、置信度和是否人工修正。
- 球员身份确认和换边记录。
- 比分、发球方、赛制和场地模式。
- 数据缺失区间、最长断轨、ID-switch和质量告警。
- 回合、击球和评分的证据帧范围，便于人工复核。

## 火柴人回放能力

只要拥有球员球场坐标和时间戳，就能生成俯视球场上的球员移动回放。当前真实解析结果已经足以驱动两个球员的位置动画。要让球也准确出现在标准球场上，至少需要球的近似球场坐标；当前真实输出只有球的像素坐标，因此可以准确叠加在原视频上，但俯视球场中的球只能近似投影。

本目录的 `stick_match_10s.mp4` 使用合成的球员球场坐标和羽毛球三维轨迹生成，用于证明数据合同可以驱动简易回放，不代表当前模型已经恢复出真实三维球路。
