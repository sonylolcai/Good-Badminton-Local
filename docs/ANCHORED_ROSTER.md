# 同帧人物照片组与连续关联

`anchored_roster.v1` 用于标准羽毛球流式比赛。单打建立两个匿名人物参考，双打建立四个；初始排序只用于生成 ID，后续左右位置与所在半场不定义人物身份。账号、姓名和本人认领仍归业务服务处理。

## 照片与身份参考

先观察阵容人数与半场分布，再选择一张所有参赛者同时有清晰、互不严重重叠人体框的实际源帧。参考帧需有肩、髋、脚踝姿态支持，只有腿部、裁出画面或模糊的框不能建立参考。默认远端增强区域为此增加竖向人体空间；原四角地面标定与 TrackNet 保持既有输入。显式摄像头 ROI 仍按配置使用，若裁掉人体则不会凭空补全照片。

照片按整组写入临时目录，所有 JPEG 与 manifest 成功后一次重命名为 `candidate_photos/anchor_set`。每张照片有相同的 `photo_set_id`、`source_frame_index` 与 `source_time_sec`，以及各自的 SHA-256；写入后不单独替换某人的照片。初始衣着参考保持固定；另有最多八个样本的多朝向参考库，用于已经确认的连续轨迹中的外观变化。中断恢复必须核对整组文件及 checkpoint。提交前写盘失败不暴露半组；提交后重放同一帧复用原组。

## 关联与不确定性

连续画面结合前一人体框重叠、合理运动、双向唯一分配与衣着无冲突证据维持匿名 ID。缺少短时连续性时，要求固定衣着参考给出双向明确匹配且运动合理。观测不能按“同半场最近空位”自动继承身份，也不会根据 ByteTrack key 单独认定身份。

连续性也不能覆盖明确的反向外观证据：如果当前观测明显更像另一人物 ID，即使该 ID 处于 missing，位置较近的 ID 也不能接管。超过 0.5 秒的观测间隔后，若新旧测量都离网线超过既有 0.8 米运动门限，且位于相反半场，缺少中间过网证据时保持未知；确实逐帧观测到的跨网移动仍可维持同一 ID。此限制避免把断轨后的远距离跳转解释为同一人横穿球网。

持续跟踪的空间过滤与上游 `contains_athlete` 使用同一份既定观察边界，不再因为脚点投影到底线外几厘米就丢弃完整人体框。初始阵容仍要求场内平衡开局；旁观者与超出既有观察边界的观测继续排除。这是消除上下游过滤不一致，不是扩大标定或调低身份匹配阈值。

`continuous-views.v1` 参考库只接纳原本已通过连续跟踪判定的清晰完整人体观测。新视角必须连续至少三帧满足原有正向外观距离、竞争人物差距和躯干/定位质量要求，且不得违背初始参考的外观否决条件。缺失、恢复的首帧、含糊匹配和模糊/重叠画面不能学习；样本均留存来源帧、距离及连续确认数。原始参考与展示照片不被覆盖，最多八个样本限制开销。它不是自动训练人脸或生物身份模型，仍不能识别衣着无法区分的人物。

遮挡重叠、衣着近似且无法区分、外观明显改变或运动不可能时，对应参考保持 `identity_status=unknown`，轨迹输出 predicted/missing。超过短时恢复窗口后，要求至少三帧连续、清晰、双向唯一且按原有更严格门限匹配已确认衣着参考库的证据，才能开始新的观测片段，不能凭最近位置恢复，也不回填确认前的未知样本。下游只接受新鲜 detected 位置；缺失间隔不转成距离或速度。没有足够恢复证据时可能持续未知，不能用高覆盖率掩盖身份缺口。

当前颜色直方图距离、连续性门限、图像清晰度和姿态完整性门限是初始操作参数，没有经过独立身份标注校准。`association.identity_confidence` 沿用既有统计准入信号，不能解读为测得的人物身份概率。颜色相同的人、光照变化和长遮挡仍是限制；同帧照片正确不代表整场身份准确率已验证。

## 契约与兼容

- 输入策略为 `anchored_roster.v1`，输出 `identity_scope=individual_tracks.v1`，并保留策略版本、完整初始 ID 集合及源帧证明。匿名视觉参考不声明物理人物身份已经认证。
- 业务派生验证每个事件的策略和参考一致性，并要求完整同帧照片证明；缺失或混用旧席位事件会失败，不能仅凭配置把旧结果标成新策略。
- 正式指标中的人物 ID 决定归档照片 ID，不取开局未确认候选列表的前四项。新策略要求两张/四张照片完整归档才发布业务结果。
- 新真实场地比赛由业务端选择新策略，开赛就绪检查要求 GPU 显式声明支持；旧服务报未就绪，不降级、不启动实例。发布需协调 GPU、业务协调器与结果 worker。
- 旧 `half_court_slots.v1` 请求和历史数据保持原语义，不迁移或重写。批量整段 API 尚未接入新策略，会拒绝该策略，而不是悄悄使用旧算法。
- ByteTrack 后端沿用已有不可跨进程恢复的保护；默认 court_association 后端的新参考和照片 checkpoint 可恢复。修复重放若产生新的连续性 epoch，业务端不合并不同参考为同一人，须重新验证该场证据。
- 多朝向库 checkpoint 含独立版本 `continuous-views.v1`、原始参考、各视角来源和待确认状态；不支持的库版本、缺少来源、第一项与原始参考不同或非法样本应拒绝恢复。旧版只有原始参考的 checkpoint 可安全恢复为单样本库，不能假造历史新视角。实际实现内容由现有推理流程 SHA-256 区分，旧产物不被覆盖。

## 验证边界

确定性测试覆盖单/双打同帧照片、缺人/模糊/腿部框/重叠拒绝、交叉顺序、异常 key、身份歧义、短缺失与长缺失、整组写盘失败、重启恢复、正式照片读取、最终状态元数据，以及业务派生/归档一致性。测试不提供真实身份准确率。

真实录像仅通过本机 MPS 与标准 8082 服务，保留原始事件、源片哈希、策略与实际源码版本。真实样例截图需逐一核对人数和完整性；整场 ID 切换率需要独立逐帧人物标注。传输成功、处理 finalized、照片同帧与身份准确率是不同结论。

## 所有参赛者联合回归

单打两人或双打四人必须在相同输入、相同标定、相同测量时钟和预先声明的时间范围内一起比较。使用业务仓的 `tools/evaluate_player_regression.py` 读取已有流式事件/回放轨迹及原始视频分片哈希，不产生新推理、网络请求或发布操作。统计准入复用业务服务实际使用的 `collect_track_position_evidence`，不能把 detected 数量当成可用于统计的数量。

每个版本分别输出每人、每个时间段及全段的有效覆盖、缺失/预测/缺行数与最长未关联区间，同时输出四人同时有效的次数。被漏掉的人物行仍占原先的分母；不能靠少输出某个人或缩短评测范围提高覆盖。参考照片/人物初始帧不同、原视频/标定/时钟不同的版本拒绝直接比较。

身份复核输出物理人物到预测 ID 的混淆表，并保留未知和非参赛者；逐项检查错归、同一人体框被两个 ID 使用，以及旧版本本来正确的样本是否在新版本丢失。任何一人或任一固定时间段的覆盖下降，都单独阻断自动接受并要求检查原因；即使下降是为了纠正旧版错归，也必须有相应证据，不能被另一人的提高或全队平均分掩盖。抽样无错不代表全部逐帧准确率通过，工具不会授权上线。

退出码：`1` 表示至少一个对照发现退化或错误，`2` 表示尚缺完整独立身份真值，`0` 仅表示本次输入上的联合检查未发现退化，仍不代表发布授权。未通过整段人物持续跟踪验收前保持不上线。

## 固定参赛者先验与联合补全试验

用户明确本场参赛者默认不会中途更换。离场时继续保留原 ID、照片及参考；返回后使用固定的两人/四人名单参与身份匹配。此业务先验不代表入镜旁观者自动成为参赛者，也不意味着检测人数恢复就可以按位置填席位。

`outputs/fixed-roster-recovery-20261113/prototype/` 的候选增加一条有独立证据的补全路径：其他 N−1 个身份已经唯一归属、当前恰有 N 个清晰完整人体框、最后一个身份仍有当前 ReID 正向关联，并且完整一对一排列与所有已确认归属一致。排列必须连续至少三帧唯一成立，使用现有神经正向距离门限和更严格的 0.20 组合差距判据；运动、跨网和明确反向外观证据仍能否决补全。多个身份同时未定、重叠/不完整人体、多出场内人物、排列并列、证据中断均保持未知，不回填确认前的样本。组合判据属于新增实验恢复路径，需要更多录像验证，不能将其差距解释为身份概率。

补全的人数检查会忽略上游 association key，仅保留原有空间重复过滤，避免重复 key 将真实的第五个身体框隐藏掉。原来的两个关联分支仍独立更新，融合和补全结果不反向训练它们。实验 checkpoint 使用独立版本并拒绝恢复，常规 tracker 同样拒绝读取。

同一历史 60 秒样本通过本机 MPS／8082 实际处理 30/30 个分片，TrackNet、标定与四张参考照片不变。业务统计有效点数由上一轮安全候选的 `[413,461,422,453]` 变为 `[418,461,422,453]`，每人分母仍为 557；固定的每人、每个时间窗检查无退化。补回 1 号在 26.3、26.4、39.3、39.4、39.5 秒的五个样本，全部核对原图。实际 2,228 个人物关联结果与已有本机 MPS 特征重放一致；26 项控制测试通过，包括交叉、长遮挡、单/双打、固定名单补全、证据中断、额外人物和重复 key。

扩展到 926 个原图裁片的定向 AI 复核中，候选接受的 612 个裁片未发现错归。新增复核还发现旧 ReID 在 38.2 秒把 1 号赋给 2 号、50.7 秒把 2 号赋给 1 号；本候选保持未知。相对该旧实验仍少 9 个有效点，其中六个是已经发现的错归或混合身体，另外三个是 39.1 秒 2 号及 42.7、42.8 秒 1 号的正确样本被拒绝。这个残余回归继续记录，不能靠总和改善抵消。

本轮只证明固定参赛者先验帮助了这五个样本；全段持续身份验收仍未通过，定向 AI 复核不能代替完整独立身份真值，原先报告问题的新比赛也未重新评测。候选没有接入默认运行策略或部署，试验后标准本机 MPS 服务已恢复。证据见新任务目录的 `summary.json`、`mps-report.json`、`complement-evidence.json` 和 `task-record.json`。

## 三处残余样本：部分阵容约束与有界延迟确认

`outputs/partial-roster-recovery-20261113/` 保留本轮试验。42.7、42.8 秒近场两人遮挡，只有远场两个完整身体，原先的完整阵容判据会丢掉远场 1 号。新候选枚举使用既有运动/跨网否决条件的可行阵容，但分别计算每个清晰人物的归属差距和连续确认数。不完整身体只提供位置约束，不能因此被赋予 detected 身份；两个隐藏队友的排列歧义不再重置另一人的独立证据。补回的人仍需当前 ReID 正向关联、原有距离和反向外观检查，三帧确认与 0.20 归属差距条件保留；若外观与同半场另一人接近，该人还需有自己独立的当前 ReID 正向锚点，不能靠运动从一对外观并列的人中制造身份。

39.1 秒的 2 号不同：38.8、38.9 秒只有定位规则拒绝的上半身检测框，无法凑足三帧清晰证据。候选采用有界的两次测量延迟，10Hz 时为 0.2 秒。独立提议分支处理当前帧；提交分支只按原始时间处理缓存帧。39.1 秒的源帧 1173 在 39.3 秒收到 1173、1176、1179 三个真实源帧的完整确认后，才发布原始测量。没有改写此前已发布的 unknown，也没有把未来的位置、姿态或时间当成 39.1 秒的数据。提议分支不接收提交结果的反馈。

人物参考照片建立前不延迟，以保留原始同帧截图。此后事件按人物提交水位统一排序，包含原 TrackNet 事件，避免人物延迟使公共时间轴倒退。视频尾部缓存会全部刷新，没有未来证据的测量保留未知；检查点采用实验版本，原生与实验恢复均拒绝静默丢掉缓存后续跑。该延迟、事件水位及新身份来源尚未形成正式发布契约。

同一历史 60 秒录像经标准本机 MPS／8082 实际完成 30/30 分片。每人 557 个机会，业务有效点数由 `[418,461,422,453]` 变为 `[420,462,422,453]`，39.1、42.7、42.8 三处均恢复；四人各固定时间窗无退化。全部 2,228 个人物输出与重放一致，1,793 个 TrackNet 测量逐项不变，四张参考照片哈希不变。最终 registry 计数与已发事件一致，尾部未漏行，事件源时间单调。

原有 26 个控制场景及新增 9 个缓冲/部分阵容场景通过，新增测试另重跑了其中 8 个旧场景。累计 964 个人物裁片的定向 AI 复核中，候选接受的 634 个未发现错归。与旧 ReID 相比少的六个 detected 点，全部对应已复核的四个错归和两个混合身体，没有此前正确的复核样本新增丢失；原始覆盖下降警报仍保留，没有用修正旧错归为由删除对照记录。

三处目标的本地复验已通过，完整比赛持续身份验收仍未通过：尚无完整独立逐帧身份真值，原报告的新比赛未重测，新来源还未接入原生 registry 的可信恢复来源契约（原生会保守累加不确定恢复计数），模型流程签名、缓存恢复及延迟发布亦待正式集成验证。因此候选只留在任务目录，没有替换默认策略或部署；试验后常规本机 MPS 服务已恢复。
