# 视频资源生命周期与后台管理实施结果

## 已交付

- 业务平台与评测平台使用独立资源账本、数据库 schema 和磁盘根目录。
- 两个平台均支持“仅删除资源”和“删除全部数据”；仅删除资源保留记录与 JSON，全部删除清除所属数据记录。
- 本地磁盘与已登记 GPU 位置按逐位置状态同步删除；部分失败返回可重试状态，不伪报完成。
- 视频保留期以上传成功时间计算，默认 7 天且开关默认关闭；开启后由单实例 worker 每日协调两平台，只删除视频。
- 业务网站使用账号密码、HttpOnly 会话和固定 RBAC：平台管理员全局，球馆管理员仅所属球馆；球员没有登录身份。
- 后台已增加登录/首次改密、管理员与球员、视频资源、手动解析、删除动作和保留策略页面。
- 存储位置已抽象为 `local_disk|gpu_http|object_storage` 账本；本轮不绑定具体对象存储供应商。

## 部署顺序（未执行）

1. 备份业务库、评测库和视频目录；准备独立的测试或生产数据库连接。
2. 在业务环境文件配置 bootstrap 管理员、会话、业务媒体根目录、评测 API/内部密钥和允许的 Web 来源；初始密码只放环境密钥，首次登录立即修改。
3. 使用现有 `deploy/business-server/apply_migrations.py` 应用业务 migrations，确认 `0010_admin_auth_media_resources.sql` 已记录。
4. 以具备建表权限的账号执行评测 `backend/migrations/0003_resource_lifecycle.sql`，传入受限应用角色变量 `evaluation_role`。
5. 先启动业务/评测 API 并检查登录、资源清单和内部清理鉴权，再启动独立 `retention-worker`。
6. 保持自动清理关闭；用测试视频分别演练“仅删除资源”和“删除全部数据”，确认 JSON 保留与跨球馆 403 后，再由平台管理员打开 7 天策略。
