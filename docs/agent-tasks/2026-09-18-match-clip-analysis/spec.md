# 单局双轨录像、分片分析与受限母版修复

## 目标

现有“开始采集”创建一局 ID，场馆端从同一编码时间线同时产出：

1. 两秒 MP4 分片，实时上传给 GPU 分片分析；
2. 一条本地完整母版 MP4，停止后上传业务服务器。

“停止视频”结束该局。服务器以母版作为用户原始录像、最终标注成片和 VLM/LLM 复盘的权威源；以分片作为实时 GPU 输入与断网恢复源。母版和分片不相互硬拼，只按本局 PTS/时长/抽样帧校验覆盖一致性；母版不可用时，连续分片合成的 `recording.mp4` 才是明确标记的 fallback。

## PTS

PTS 是某帧在本局开始后的展示时间。它不改变画质或传输量，只将实时 GPU 证据、母版帧和最终标注绑定到同一位置。当前 `segment_index * 2` 是基础相对时间线；母版与每段的实际 PTS 必须在整个 session 中连续。

## 母版修复策略

母版**默认不跑 YOLO Pose、羽毛球检测或整局 GPU 分析**。正常结果只由两秒分片的顺序 GPU 会话和检查点融合而成。

仅当质量门控产生明确 repair ticket 时，才从母版取含前后上下文的小窗口复算。初始门槛故意极严格：

- 分片缺失、GPU 失败或 checkpoint 无法恢复；
- 在同一局连续 10 秒内，人员关联持续 `unknown` 或预计运动员有效观测覆盖低于 20%；
- 在已确认进行中的回合中，连续 10 秒没有可信的球或人体测量证据；
- 母版与分片的 PTS/时长/抽样帧校验不一致。

修复只能替换对应 PTS 窗口中质量更高的证据，并保留原始证据、原因和前后结果；源流真实缺帧只能标记为 `unknown`，不能捏造。阈值应是服务端配置，不放在运营 UI；后续以真实场馆质量数据调整。

## 当前可复用行为

- 场馆 agent 已在 `record` 下创建一次 session、产生两秒 H.264 MP4，并在 `idle` 下完成 session。
- edge gateway 已保留分片、拒绝缺段完整封存，并以 `-c copy` 产生 fallback `recording.mp4`。
- GPU `AnalysisEngine` 已有顺序片段、checkpoint、恢复、乱序等待和重复幂等能力。

## 接受标准

- `AC-01`：开始/停止采集各创建/结束一个对局 ID；同一编码过程同时得到分片和本地母版。
- `AC-02`：母版上传后具有 SHA-256、时长、PTS 范围和状态；业务服务器保留它与 fallback 的明确来源关系。
- `AC-03`：同局分片在一个可恢复 GPU 会话中顺序处理；重传不重复，正常结束不触发母版整局重跑。
- `AC-04`：最终用户视频从母版和统一 PTS 标注一次渲染；母版失败才允许标记为 fallback 的分片合成视频。
- `AC-05`：修复任务仅覆盖被质量门控选中的小窗口，记录触发原因、输入/输出证据和是否改善；初始软阈值难以触发。
- `AC-06`：VLM/LLM 仅消费带 PTS 的母版窗口、关键帧和已知 CV 事实；输出是解释性/待核验建议。

## 不在范围

- 全天采集、额外开始/结束对局按钮、WebRTC 归档。
- 正常对局的母版全片二次 GPU 分析。
- 具体 VLM/LLM 厂商、密钥、自动裁判或不经人工校验的能力结论。
