# 羽毛球回合结束证据约束

适用范围：`sports/physics.py`、`sports/badminton.py` 与
`tools/render_lightweight_tracknet_ball.py` 离线分析路径。尚未接入远端 GPU API。

## 当前行为

- 不按视频名称、绝对时间、固定帧号或回合编号指定开始、拍数、动作和结束。
- 用实际观测的连续运动形成候选片段。起点表示“从这里观测到运动”，不等价于发球或正式回合开始；`start_confirmed=false`。
- 单点低速、遮挡、追踪丢失和视频结束均不能直接判死球。没有结束证据时保留 `terminal=null`。
- 连续真实观测同时满足“相邻观测速度不超过阈值”和“窗口内任意两点位移不超过阈值”，并持续达到配置时长时，生成推断落地信号。用窗口坐标中位数估计落点；有场地标定则判断界内/界外，无标定则仅生成 `dead_ball`。
- 推断落地记录 `evidence=low_speed_low_displacement`，与直接落地证据 `ground_contact` 区分。事件时间是条件满足的确认时间，不冒充精确触地时刻。丢失、插值、超速、超位移或采样间隔过大会重置窗口。
- 真实观测中有 `ground_contact=true` 时确认死球；同时提供当前画面的场地多边形，才按落点判断界内/界外。压线按界内处理。
- `predicted`、`interpolated` 位置不作为落地、静止和运动起始证据。可视化仍可显示它们。
- 不产生得分方、比分或发球权。起点未确认时，正式回合数和有效回合状态保持未知；轨迹分段数不冒充真实拍数。
- 正反手、击球者、击球类型与空间分区在缺少独立证据时为 `unknown`。没有三维/尺度证据时，公里时速为 `null`。

## 配置与输入

通用观测阈值位于 `badminton_analysis/sports/observation_defaults.json`，可用
`--analysis-config <JSON路径>` 覆盖。它们是待评测的检测参数，不是某个视频的答案：

| 参数 | 含义 |
| --- | --- |
| motion_min_speed_diagonals_s | 候选运动的最低图像速度，单位为画面对角线/秒 |
| motion_min_duration_s | 候选运动最短持续时间 |
| stationary_duration_s | 确认持续静止的时间 |
| stationary_radius_diagonals | 低速窗口内任意两点的最大位移，单位为画面对角线；沿用原配置名 |
| stationary_max_speed_diagonals_s | 窗口内相邻真实观测的速度上限，单位为画面对角线/秒 |
| max_observation_gap_s | 连续观测允许的最大采样时间差 |
| turn_angle_degrees | 轨迹候选分段的方向变化阈值，不代表已确认触拍 |

### 分辨率适配

按实际输入画面的对角线 `D = sqrt(width² + height²)` 换算：
速度上限为 `0.01 × D` 像素/秒，窗口内最大位移为 `0.002 × D` 像素，
两项同时满足至少 0.5 秒。以下是当前默认值的换算，非已标定的最优阈值：

| 实际输入分辨率 | 速度上限（像素/秒） | 窗口内最大位移（像素） |
| --- | ---: | ---: |
| 1920×1080 | 22.03 | 4.41 |
| 2048×1080（DCI 2K） | 23.15 | 4.63 |
| 2560×1440（常称 2K/QHD） | 29.37 | 5.87 |
| 3840×2160（UHD 4K） | 44.06 | 8.81 |
| 4096×2160（DCI 4K） | 46.31 | 9.26 |

以上尺寸均有 24/30/60 FPS 的合成回归：低速小位移的界内/界外落点、
小位移高速抖动、低速大位移。速度使用实际时间差，不使用固定每帧速度。
分析使用源视频坐标；输出视频缩小不影响判断。外部缓存、球坐标和场地标定必须
处于同一坐标系。分辨率缩放适配不代表对裁剪、变焦、机位及透视变化也自动适配。

`--video-file` 必须明确指定。缓存仅在显式传入 `--cached-csv` 时使用，需要逐帧覆盖当前视频；由调用方保证缓存和视频对应。

`--court-calibration <JSON路径>` 文件包含 `image_size: [宽, 高]` 和
`court_polygon: [[x, y], ...]`。顶点必须按边界顺序排列、构成有效凸多边形，
坐标与源视频一致；单打/双打边界由标定方选择，不提供样例场地默认值。
画面大小不匹配时拒绝使用。可选检测 ROI 不代替场地边界，也不删除界外观测。

CSV 中 `ground_contact` 可为 `1`/`true`，但必须来自独立落地检测证据，
不得按时间点、人工预期回合或球在画面中的高低位置填入。
当前 TrackNet 不输出直接落地证据，但可以通过上述低速、小位移组合规则推断落地，
再结合场地标定判断界内外。此规则是可解释的运动启发式，不是新的落地识别模型；
被持住的球或误检静态背景仍可能误触发，需要真实视频评测。

## 验证和限制

回归覆盖时间平移、帧率/分辨率变化、缺失/插值证据、低速与小位移的联合判定、
场地标定、压线、不记分和未知动作标签。合成轨迹验证过 JSON 与 60 帧 MP4 导出；
合成数据中的落地标记仅用于测试。

这些测试不代表真实 GPU 推理、真实场景死球准确率或长视频稳定性已通过。
静止规则仍需评测误检背景、球员持球及镜头移动等情况。

## TrackNet 与门控的边界

TrackNet 主流程直接消费时序检测结果。在 `system.py` 中，TrackNet 分支调用
`update_external_measurement()`，明确绕过 YOLO 距离门控；轻量离线工具直接
使用 `LightweightTrackNetDetector` 的输出。流式 TrackNet 分支使用独立时序处理器。

此前新增的 `tools/run_dynamic_gated_analysis.py` 是独立的 YOLO 实验脚本，
把 TrackNet 当对比数据，并不是 TrackNet 的处理环节。仓库未发现主流程调用；
按当前仅使用 TrackNet 的需求已移除，不再扩展其动态置信度门控。
共享跟踪器内原有的 YOLO 基础过滤仍有其他调用者，因此保留。
