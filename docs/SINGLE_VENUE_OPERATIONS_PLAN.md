# 单馆单场总控方案（P0）

## 目标

先以 **好雨时节球馆 / 一号场** 跑通一个真实、可运营的闭环，再扩展多场馆 SaaS。运营人员打开一个后台即可知道：场地是否可用、终端是否在线、摄像头是否在线且已标定、解析是否正在进行、GPU 是否可用，以及最近一次失败原因。

这不是独立的球馆网站；它是统一后台中的一个“单馆总控”工作区。现有“场馆与场地”总表保留为全局入口，运营人员选定一个场馆后进入该场馆的总控视图。

## 一号场的真实状态模型

| 对象 | 状态 | 数据来源 | 可以做的操作 |
| --- | --- | --- |
| 场馆 | `active` / `inactive` | `business.venues` | 启用、停用 |
| 场地 | `active` / `maintenance` / `inactive` | `business.courts` | 设为维护、恢复可用 |
| 终端 | `online` / `offline` / `disabled` | 签名心跳 + `edge_devices.last_heartbeat_at` | 生成/轮换终端凭据、禁用终端 |
| 摄像头 | `active` / `offline` / `disabled` | 签名心跳 + `cameras.last_heartbeat_at` | 绑定或禁用摄像头 |
| 标定 | `draft` / `validated` / `invalidated` | `camera_calibrations` | 提交四角、验证、摄像头移动后作废 |
| 解析会话 | `requested` / `receiving` / `relaying` / `processing` / 终态 | `edge_ingest_sessions` | 开始、查看进度、结束、取消 |
| GPU | `not_checked` / `ready` / `unavailable` | 业务端健康检查 | 保存服务端地址、检查、受控启停、取消任务 |

“在线”仅由最近一次有效签名心跳计算，不能由页面点击或终端自报场馆/场地归属决定。终端只携带 `device_id`、`camera_id`、时间戳、nonce、请求摘要和签名；业务服务器按数据库绑定关系解析场馆和场地。

## 页面与操作顺序

1. **场馆与场地总表**：一行一场地，显示球馆、场地、场地状态、终端、摄像头和解析状态；不把 UUID 当作主界面内容。
2. **单馆总控**：选择“好雨时节球馆”后，只显示其场地和六个状态卡：数据库、业务网关、终端、摄像头/标定、解析会话、GPU。
3. **首次部署**：创建/绑定终端和摄像头，复制一次性配对数据到受控终端；终端 RTSP 地址和密码永远不写入后台。
4. **标定**：保存四个场地角点并标记 `validated`。镜头位置、焦距、裁切发生变化时必须标为 `invalidated`，不允许继续把结果当作可比较的运动数据。
5. **开始解析**：终端先心跳，再请求业务网关创建会话；业务网关读取已验证标定，暂存闭合分片并同步转发 GPU。只有取得 GPU 回执才把分片标为已转发。
6. **结束解析**：终端提交最后分片后，使用同一签名语义通知业务网关完成 GPU 会话；后台只在 GPU 回执后显示成功、部分成功、失败或取消。

## 数据与网络边界

```text
摄像头 → 场馆终端 → 业务网关 → GPU
                     ↓
              PostgreSQL 状态/回执
```

- P0 不使用 OSS：视频字节只在业务网关暂存到收到 GPU 回执；数据库仅保存哈希、索引、状态与回执。
- GPU 只获得匿名摄像头/标定/分析配置与分片；用户、队伍、比分、积分不跨越该边界。
- 当前本地 WebUI 没有登录/RLS，因而只能监听本机或受控内网；公网部署前必须接入服务端身份验证和角色校验。
- GPU 的“启动/关闭”只在服务端预配置受控适配器时可执行；未接入云厂商 API 时应显示“外部托管，仅健康检查”，不能假装已启动。

## P0 验收

以“好雨时节球馆 / 一号场”为准，以下全部成立才进入现场摄像头测试：

1. 总表能从 PostgreSQL 显示该场馆、该场地及其 `active` 状态。
2. 终端在两分钟内发出有效心跳后，后台显示设备和摄像头在线；过期后显示离线。
3. 未验证标定时，业务网关拒绝创建解析会话；标定失效后同样拒绝。
4. 终端提交一个含时间戳、nonce、签名、SHA-256 与幂等键的闭合分片；后台显示已收、已转 GPU、GPU 会话 ID 或明确错误。
5. 重复提交相同分片不重复计算；同索引不同哈希明确报冲突。
6. GPU 不可达时，后台显示失败和最近错误，不能显示“解析成功”。
7. 结束会话后，状态只能进入 `succeeded`、`partial`、`failed` 或 `cancelled`；没有 GPU 回执不允许显示完成。

## 本阶段不做

- 多租户登录、套餐、订阅支付、账单和 SaaS 自助开通；
- 公网实时预览/WebRTC/HLS；
- OSS/NAS 长期录像与用户回放；
- 未经现场验证的自动标定、自动计分或精确 3D 结论。

完成 P0 验收后，SaaS 的第一步才是把现有 `tenant → venue → court` 数据模型接入真实身份认证、角色权限和租户隔离，而不是先加支付页面。
